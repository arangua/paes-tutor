# FUTURES ROADMAP — PAES-Tutor (Uso real)

## 1. Propósito
Este roadmap guía la evolución del sistema durante su uso real por usuarios finales.
Prioriza correcciones, mejoras de experiencia y pequeñas funcionalidades, manteniendo
íntegro el baseline Enterprise existente.

---

## 2. Principios (no negociables)
- No se relajan guards, CI, seguridad ni baselines.
- Todo cambio pasa por PR (aunque el plan no lo fuerce).
- Cambios pequeños, iterativos y reversibles.
- Feedback de usuarios reales manda la prioridad.

---

## 3. Alcance permitido (en este ciclo)
### Incluye
- Bugfixes funcionales
- Mejoras de UX/UI
- Ajustes de textos, flujos y validaciones
- Pequeñas features solicitadas por usuarios
- Optimización de performance local

### Excluye (requiere nuevo ciclo)
- Cambios de arquitectura
- Nuevos módulos grandes
- Cambios de seguridad/CI
- Integraciones externas complejas

---

## 4. Flujo operativo (simple)
1. Usuario reporta problema o necesidad.
2. Se registra como ítem en este roadmap.
3. Se implementa en rama.
4. Se valida con el usuario.
5. Merge consciente a `main`.

---

## 5. Backlog (vivo)
> Se llena solo con feedback real.

### Bugs
- [ ] (vacío)

### UX / Usabilidad
- [ ] (vacío)

### Features pequeñas
- [ ] (vacío)

---

## 6. Métrica de éxito
- Usuarios pueden usar el sistema sin fricción.
- Menos preguntas repetidas.
- Menos errores "obvios".
- Sensación de fluidez y confianza.

---

## 7. Cierre de este ciclo
Este ciclo se cerrará cuando:
- el uso se estabilice,
- no aparezcan issues recurrentes,
- o se decida iniciar un ciclo mayor.

El cierre se formaliza con un Acta de Cierre.
